# Movie Watchlist

## 1. Описание проекта

**Movie Watchlist** — кроссплатформенное мобильное приложение на Flutter для поиска фильмов и управления личным списком просмотра.

Приложение позволяет пользователям находить фильмы, просматривать информацию о них, сохранять фильмы в список просмотра, отмечать просмотренные фильмы, выставлять оценки и оставлять отзывы.

## 2. Цель проекта

Разработать удобное мобильное приложение для организации личной библиотеки фильмов с возможностью поиска, локального хранения данных и синхронизации пользовательской информации между устройствами.

## 3. Целевая аудитория

Приложение предназначено для пользователей, которые регулярно смотрят фильмы и хотят:
- сохранять фильмы, которые планируют посмотреть;
- отслеживать просмотренные фильмы;
- вести собственную историю просмотров;
- выставлять оценки и писать отзывы;
- получать информацию о фильмах в одном приложении.

## 4. Аналоги

- **IMDb** — каталог фильмов, информация об актёрах, рейтинги и пользовательские оценки.
- **Letterboxd** — личный дневник просмотров, оценки, рецензии и списки фильмов.
- **Trakt** — отслеживание просмотренного контента, история просмотров и персональные списки.

Movie Watchlist будет ориентирован прежде всего на простой персональный список фильмов и удобное отслеживание просмотров.

## 5. Основные экраны

1. **Главная** — популярные фильмы и рекомендации.
2. **Поиск** — поиск фильмов по названию и просмотр результатов.
3. **Информация о фильме** — постер, описание, жанры, дата выхода и рейтинг.
4. **Мой список** — фильмы, добавленные для просмотра, и просмотренные фильмы.
5. **Профиль** — авторизация, пользовательские оценки и отзывы.
6. **Настройки** — выбор темы оформления и управление настройками приложения.

## 6. Планируемые технологии

- Flutter и Dart с null safety.
- Material 3 для пользовательского интерфейса.
- Provider для базовых сценариев управления состоянием.
- Riverpod для основной бизнес-логики и внедрения зависимостей.
- Архитектура presentation / domain / data с использованием Repository.
- REST API для получения информации о фильмах.
- JSON для обмена данными.
- SharedPreferences для настроек и Hive для локального хранения фильмов.
- GoRouter для навигации.
- Firebase Authentication для регистрации и входа.
- Cloud Firestore для хранения и синхронизации пользовательских данных.
- Firebase Cloud Messaging для push-уведомлений.

## 11. Неделя 3: состояние списка просмотра

Одна функция — добавление и удаление Interstellar из списка — последовательно реализована в трёх сохранённых запускаемых версиях:

```text
flutter run -d chrome -t lib/learning/week_03/set_state_demo.dart
flutter run -d chrome -t lib/learning/week_03/inherited_demo.dart
flutter run -d chrome -t lib/learning/week_03/provider_demo.dart
```

В каждой версии кнопка «Добавить» меняет счётчик с 0 на 1, «Удалить» возвращает 0. У них общий UI, но отдельные способы владения и передачи состояния. Каждая версия покрыта отдельным widget-тестом.

| Подход | Плюсы | Минусы | Когда применять |
| --- | --- | --- | --- |
| setState | Прост для локального состояния, не требует пакетов | Данные и обновление связаны с State; передача между экранами требует ручных параметров | Небольшой виджет, локальная форма, выбранная вкладка |
| InheritedWidget | Передаёт данные зависимым потомкам без цепочки параметров | Сам не хранит изменяемое состояние; нужны владелец, callback и updateShouldNotify | Собственная область общих данных, изучение механизма зависимостей Flutter |
| Provider + ChangeNotifier | Отделяет состояние от UI, управляет временем жизни, обновляет подписчиков | Дополнительный пакет; требуется правильная область Provider и notifyListeners | Общий изменяемый список на нескольких экранах |

InheritedWidget-версия сохраняет setState у владельца: InheritedWidget доставляет снимок состояния и сообщает зависимым потомкам об изменении. В Provider-версии владелец — WatchlistModel, изменения сообщаются через notifyListeners; UI использует watch для подписки и read в обработчиках. См. [документацию Provider](https://pub.dev/packages/provider).

Основное приложение работает на Provider: кнопка страницы фильма изменяет общий список, коллекция отображает его и позволяет удалить фильм. Список изначально пуст, хранится только в памяти и сбрасывается при полном перезапуске. «Просмотрено» и «Избранное» остаются явно обозначенными демонстрационными разделами.

[Отчёт и доказательства последовательных этапов](docs/week_03_report.md). Формат сдачи преподавателя сверх исходного задания пока не предоставлен; запускаемые примеры сохраняются и после будущего перехода на другой подход. Commit и push не выполняются.

## 12. Неделя 4: Riverpod, Repository и DI

Основное приложение теперь работает на Riverpod. Provider и WatchlistModel сохранены только для учебной версии недели 3; её команды запуска по-прежнему действуют. Описание недели 3 выше отражает результат того этапа.

```text
lib/domain/        модели и договоры репозиториев, без Flutter/Riverpod
lib/data/          реализации репозиториев и статический каталог
lib/presentation/  экраны, виджеты, темы, Riverpod-контроллер
lib/app/           выбор конкретных репозиториев и внедрение зависимостей
lib/learning/      сохранённые учебные версии
```

Экраны получают каталог через catalogProvider и список через watchlistProvider. WatchlistController делегирует запись WatchlistRepository. Конкретный InMemoryWatchlistRepository создаётся в app/providers.dart и заменяется через Riverpod overrides в тестах. Механизмы [провайдеров](https://riverpod.dev/docs/concepts2/providers) и [подмен зависимостей](https://riverpod.dev/docs/concepts2/overrides) описаны в документации Riverpod.

Старые файлы screens, widgets, theme, models и sample_data сохранены как экспорты новых путей: это совместимость импортов, а не вторые реализации. Интерфейс и данные модели перенесены без изменения дизайна. Выбор вкладки остаётся локальным setState; основная логика списка использует только Riverpod.

Репозитории пока синхронные и работают в памяти. REST API, асинхронная загрузка каталога, локальное хранение и Firebase относятся к следующим этапам и ещё не реализованы.

## 13. Неделя 5: REST API и JSON

Подключён TMDB API v3 через http: каталог, поиск с debounce 400 мс, детали и постеры. Добавлены loading/success/error/empty и pull-to-refresh. Данные сериализуются json_serializable; команда генерации — `dart run build_runner build`.

В текущем проекте ключ уже сохранён в локальном `.vscode/tmdb.local.json`. Обычный запуск из терминала:

```text

```

Приложение автоматически читает этот JSON через Flutter assets перед созданием репозитория. VS Code и дополнительные параметры не нужны. На другом компьютере создайте `.vscode/tmdb.local.json` с полем `TMDB_API_KEY` и своим ключом v3. Файл исключён из Git; ключ не записан в Dart-код. При необходимости явно переданный `--dart-define` имеет приоритет. Без доступа отображается ошибка настройки, демонстрационные фильмы не выдаются за сетевые данные. Автоматические тесты используют явную подмену источника.

Локальный JSON входит в собранное приложение как asset: в веб-версии ключ доступен браузеру. Исключение из Git защищает репозиторий, но не делает клиентский ключ секретом для пользователей опубликованной сборки.

## 14. Неделя 6: локальный кинодневник и офлайн-кэш

Hive сохраняет список просмотра, избранное, историю просмотренных фильмов, личные оценки 1–10 и отзывы. Оценка и впечатление редактируются на странице фильма. Экран личных отзывов показывает постеры, звёздную оценку и фрагмент текста; поиск работает по названию и отзыву, а записи с текстом и оценки без отзыва сгруппированы отдельно. Переход из отзыва открывает тот же фильм и прокручивает к редактору. Рейтинг TMDB остаётся отдельным от личной оценки.

Профиль содержит имя, необязательный email, аватар, статистику и записи личного дневника. Изначально личные поля пустые; вместо отсутствующего адреса показано «Email не указан». Данные профиля сохраняются отдельно в Hive (`profile_v1`). Фото выбирается через file_selector (JPG/PNG/WebP, до 5 МБ), копируется и уменьшается до 512 пикселей по длинной стороне. Сохранение фотографии не зависит от пути к исходному файлу.

Настройки открываются через шестерёнку в профиле. SharedPreferences сохраняет тему (тёмная/светлая/системная) и язык (русский/английский). Язык влияет на интерфейс и новые запросы TMDB. Уже сохранённые названия и личные отзывы не переводятся автоматически. Локальные записи сохраняются в Hive независимо от входа.

Главная сначала показывает сохранённый каталог и обновляет его из сети. При ошибке остаются данные кэша с пояснением. Hive также сохраняет сведения о фильмах и результаты ранее выполненных поисков; новые поисковые запросы требуют сети. Загруженные постеры сохраняются как байты изображений; изображения, которые ещё не загружались, офлайн заменяются заглушкой. Первому запуску с пустым кэшем нужен интернет.

Обычная команда остаётся прежней:

```powershell
flutter run -d chrome
```

`web_dev_config.yaml` задаёт постоянный адрес `http://localhost:7357`, поскольку браузерное хранилище зависит от адреса, включая порт. На вебе данные принадлежат конкретному профилю браузера. Завершайте сеанс Flutter клавишей `q`, а затем запускайте снова; используемый SDK сохраняет данные своего профиля Chrome в локальном `.dart_tool/chrome-device`. Смена браузера/профиля, очистка данных сайта или `.dart_tool` могут сделать прежние записи недоступными. Полный перезапуск Chrome требует ручной проверки по отчёту; агент не выдаёт его за проверенный. Если порт занят другим процессом, сначала освободите его; команда запуска не должна незаметно переходить на другой порт.

При отсутствии интернета веб-приложению всё ещё нужен доступ к локальному dev-серверу для первоначальной загрузки самой страницы. Установка PWA и офлайн-доставка файлов приложения в этот этап не входят.

## 15. Неделя 8: Firebase

Firebase-параметры задаются по платформам в локальном `.vscode/firebase.local.json` (пример: `.vscode/firebase.local.example.json`). Локальный файл исключён из Git; в нём находятся только клиентские Firebase identifiers, Google OAuth client IDs и публичный Web Push VAPID key. **Не помещайте туда service-account JSON или приватные ключи.** При заполненной конфигурации приложение инициализирует Firebase; без неё локальный режим и Hive продолжают работать, а экран входа сообщает, что внешняя настройка не завершена.

В Firebase Console нужно зарегистрировать используемые приложения, включить Email/Password и Google в Authentication, создать Cloud Firestore и применить [`firestore.rules`](firestore.rules). В правилах доступ ограничен документами текущего UID. Для Chrome также нужен Web Push certificate key (VAPID); Chrome разрешит push на localhost либо HTTPS и только после согласия пользователя. Для Google-входа Android Firebase Console требует SHA-1 приложения. Push-токен регистрируется кнопкой в аккаунте и сохраняется в Firestore под UID; тестовое сообщение отправляется из Firebase Console, не из клиента.

Неделя 6 включает редактор оценки и отзыва на странице фильма, локальный профиль, настройки, список отзывов и локальное хранение. Навигационные и адаптивные изменения недели 7 описаны в [отчёте недели 7](docs/week_07_report.md).

Firebase CLI связан с проектом `movie-wathclist`. Web-приложение зарегистрировано; реальная клиентская конфигурация и публичный FCM Web Push VAPID key находятся в Git-игнорируемом `.vscode/firebase.local.json`. Email/Password и Google включены в Firebase Authentication. Cloud Firestore создан в `me-central2`, а `firestore.rules` успешно опубликованы. Анализатор, 72 теста и Web-сборка проходят. Вход в приложении, облачная синхронизация и фактическая доставка push ещё не проверены end-to-end; обычный debug запуск Chrome столкнулся с аварией/зависанием Dart VM.
