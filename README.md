# Movie Watchlist

## 1. Описание проекта

**Movie Watchlist** — кроссплатформенное мобильное приложение на Flutter для поиска фильмов и управления личным списком просмотра.

Приложение позволяет пользователям находить фильмы, просматривать информацию о них, сохранять фильмы в список просмотра, отмечать просмотренные фильмы, выставлять оценки и оставлять отзывы.

## 2. Цель проекта

Разработать удобное мобильное приложение для организации личной библиотеки фильмов с возможностью поиска, локального хранения данных и синхронизации пользовательской информации между устройствами.

## 3. Целевая аудитория

Приложение предназначено для пользователей, которые регулярно смотрят фильмы и хотят:
- сохранять фильмы, которые планируют посмотреть;
- отслеживать просмотренные фильмы;
- вести собственную историю просмотров;
- выставлять оценки и писать отзывы;
- получать информацию о фильмах в одном приложении.

## 4. Аналоги

- **IMDb** — каталог фильмов, информация об актёрах, рейтинги и пользовательские оценки.
- **Letterboxd** — личный дневник просмотров, оценки, рецензии и списки фильмов.
- **Trakt** — отслеживание просмотренного контента, история просмотров и персональные списки.

Movie Watchlist будет ориентирован прежде всего на простой персональный список фильмов и удобное отслеживание просмотров.

## 5. Основные экраны

1. **Главная** — популярные фильмы и рекомендации.
2. **Поиск** — поиск фильмов по названию и просмотр результатов.
3. **Информация о фильме** — постер, описание, жанры, дата выхода и рейтинг.
4. **Мой список** — фильмы, добавленные для просмотра, и просмотренные фильмы.
5. **Профиль** — авторизация, пользовательские оценки и отзывы.
6. **Настройки** — выбор темы оформления и управление настройками приложения.

## 6. Планируемые технологии

- Flutter и Dart с null safety.
- Material 3 для пользовательского интерфейса.
- Provider для базовых сценариев управления состоянием.
- Riverpod для основной бизнес-логики и внедрения зависимостей.
- Архитектура presentation / domain / data с использованием Repository.
- REST API для получения информации о фильмах.
- JSON для обмена данными.
- SharedPreferences для настроек и Hive для локального хранения фильмов.
- GoRouter для навигации.
- Firebase Authentication для регистрации и входа.
- Cloud Firestore для хранения и синхронизации пользовательских данных.
- Firebase Cloud Messaging для push-уведомлений.

## 7. Планируемая функциональность

В рамках первых восьми недель планируется реализовать пользовательский интерфейс, каталог и поиск фильмов, просмотр подробной информации, управление списком просмотра, оценки и отзывы, сохранение данных локально, базовый офлайн-режим, навигацию и авторизацию с синхронизацией данных через Firebase.

## 11. Неделя 3: состояние списка просмотра

Одна функция — добавление и удаление Interstellar из списка — последовательно реализована в трёх сохранённых запускаемых версиях:

```text
flutter run -d chrome -t lib/learning/week_03/set_state_demo.dart
flutter run -d chrome -t lib/learning/week_03/inherited_demo.dart
flutter run -d chrome -t lib/learning/week_03/provider_demo.dart
```

В каждой версии кнопка «Добавить» меняет счётчик с 0 на 1, «Удалить» возвращает 0. У них общий UI, но отдельные способы владения и передачи состояния. Каждая версия покрыта отдельным widget-тестом.

| Подход | Плюсы | Минусы | Когда применять |
| --- | --- | --- | --- |
| setState | Прост для локального состояния, не требует пакетов | Данные и обновление связаны с State; передача между экранами требует ручных параметров | Небольшой виджет, локальная форма, выбранная вкладка |
| InheritedWidget | Передаёт данные зависимым потомкам без цепочки параметров | Сам не хранит изменяемое состояние; нужны владелец, callback и updateShouldNotify | Собственная область общих данных, изучение механизма зависимостей Flutter |
| Provider + ChangeNotifier | Отделяет состояние от UI, управляет временем жизни, обновляет подписчиков | Дополнительный пакет; требуется правильная область Provider и notifyListeners | Общий изменяемый список на нескольких экранах |

InheritedWidget-версия сохраняет setState у владельца: InheritedWidget доставляет снимок состояния и сообщает зависимым потомкам об изменении. В Provider-версии владелец — WatchlistModel, изменения сообщаются через notifyListeners; UI использует watch для подписки и read в обработчиках. См. [документацию Provider](https://pub.dev/packages/provider).

Основное приложение работает на Provider: кнопка страницы фильма изменяет общий список, коллекция отображает его и позволяет удалить фильм. Список изначально пуст, хранится только в памяти и сбрасывается при полном перезапуске. «Просмотрено» и «Избранное» остаются явно обозначенными демонстрационными разделами.

## 12. Неделя 4: Riverpod, Repository и DI

Основное приложение теперь работает на Riverpod. Provider и WatchlistModel сохранены только для учебной версии недели 3; её команды запуска по-прежнему действуют. Описание недели 3 выше отражает результат того этапа.

```text
lib/domain/        модели и договоры репозиториев, без Flutter/Riverpod
lib/data/          реализации репозиториев и статический каталог
lib/presentation/  экраны, виджеты, темы, Riverpod-контроллер
lib/app/           выбор конкретных репозиториев и внедрение зависимостей
lib/learning/      сохранённые учебные версии
```

Экраны получают каталог через catalogProvider и список через watchlistProvider. WatchlistController делегирует запись WatchlistRepository. Конкретный InMemoryWatchlistRepository создаётся в app/providers.dart и заменяется через Riverpod overrides в тестах. Механизмы [провайдеров](https://riverpod.dev/docs/concepts2/providers) и [подмен зависимостей](https://riverpod.dev/docs/concepts2/overrides) описаны в документации Riverpod.

Старые файлы screens, widgets, theme, models и sample_data сохранены как экспорты новых путей: это совместимость импортов, а не вторые реализации. Интерфейс и данные модели перенесены без изменения дизайна. Выбор вкладки остаётся локальным setState; основная логика списка использует только Riverpod.

Репозитории пока синхронные и работают в памяти. REST API, асинхронная загрузка каталога, локальное хранение и Firebase относятся к следующим этапам и ещё не реализованы.
