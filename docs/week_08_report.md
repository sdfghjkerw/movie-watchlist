# Неделя 8 — Firebase и рубежный контроль

## Реализовано в проекте

- Добавлены FlutterFire-зависимости: Firebase Core, Authentication, Cloud Firestore, Cloud Messaging и Google Sign-In.
- Firebase CLI авторизован и связан с проектом `movie-wathclist`. Зарегистрировано Web-приложение Movie Watchlist Web; его реальные клиентские настройки и публичный VAPID key сохранены в `.vscode/firebase.local.json`, который исключён из Git. OAuth client secret не загружался в локальный файл.
- Приложение загружает конфигурацию локально и инициализирует Firebase только при заполненных параметрах текущей платформы. Если настроек нет или Firebase не инициализируется, доступен прежний локальный режим с Hive.
- Добавлены экраны создания аккаунта/входа по email и паролю, вход через Google, защищённый маршрут аккаунта, выход и ручная синхронизация.
- Cloud Firestore репозиторий хранит дневник, список просмотра, профиль и FCM-токены в пространстве UID пользователя. При первом входе уникальные локальные и облачные записи объединяются; при совпадающем ID берётся локальная запись. Hive остаётся рабочей локальной копией. Изменения записываются в облако при авторизованном пользователе.
- Создана стандартная Cloud Firestore база в регионе `me-central2` (Dammam). `firestore.rules` успешно скомпилированы CLI и опубликованы в Firebase.
- Добавлена регистрация устройства в Firebase Cloud Messaging по явному согласию пользователя, обработка push в открытом приложении и Web service worker для фоновых сообщений.

## Ограничения текущей стратегии синхронизации

Синхронизация при входе объединяет записи добавлением, а совпадающий ID разрешает в пользу локальной копии. Поэтому удаление из локального списка, сделанное во время выхода из аккаунта, не имеет tombstone-записи и может быть восстановлено из старых облачных данных при следующем входе. Полный двусторонний offline-first конфликт-резолвинг не заявляется. Данные локального профиля синхронизируются в Cloud Firestore только после входа.
